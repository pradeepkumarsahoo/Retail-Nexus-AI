# Evaluation methodology

## Reproducibility
- Synthetic dataset is generated by `backend/app/data/generate.py` with a fixed seed.
- Default seed is `42`; evaluation uses the same seed.
- Reports are written to `ml/evaluation/report.json`.

## What we measure

| Task | Metrics | Baseline | Upgrade |
|---|---|---|---|
| Demand forecasting | MAE, RMSE, WAPE, sMAPE (temporal hold-out, 14-day horizon) | Seasonal naive, EMA | GradientBoostingRegressor on lag + calendar features |
| Stockout classification | ROC-AUC, PR-AUC, Brier | `1 - dos/14` clipped | LogisticRegression on (on_hand, in_transit, mean, std, cv, dos) |
| Supplier delay | ROC-AUC, PR-AUC, Brier | `1 - OTD_prior` | LogisticRegression on (otd_prior, nominal_lead_time, month) |
| Anomaly detection | Precision, Recall, F1 | — | Rolling z-score @ 2.5σ, window=28 |

## Classification claims
- Results are from the shipped synthetic dataset.
- "Synthetic test results" means the ground truth is injected at data-generation time
  and the classifier is evaluated against those injected labels.
- No real-world accuracy is claimed. A number above a baseline on synthetic data is a
  methodology demonstration, not a production KPI.

## Agent evaluation
- Fixture cases cover: routing by exception category, non-crash when product/store
  missing, recommendation schema completeness, bounded confidence, deterministic
  routing output.
- Prompt-injection refusal is tested via the mock LLM.

## Known unmeasured capabilities
- Live (OpenAI/Bedrock) latency, cost, and response-schema compliance are not measured
  unless credentials are provided and the suite is re-run under `LLM_PROVIDER=openai|bedrock`.
- No calibration tuning — baseline numbers come from the default classifier config.
